# اطلس — Atlas Scout

نسخهٔ اولیهٔ یک **برنامهٔ دسکتاپ ویندوز** برای پیدا کردن ساختمان‌های مشابه با عکس یا توضیح فارسی و انگلیسی. رابط با React ساخته شده و داخل پنجرهٔ بومی Qt WebEngine اجرا می‌شود؛ کاربر به مرورگر جداگانه نیاز ندارد.

## نسخهٔ آمادهٔ اجرا

[دانلود AtlasScout-Windows-x64.zip از GitHub](https://github.com/davidkordmir-source/S/releases/download/atlas-v0.1.0-preview.1/AtlasScout-Windows-x64.zip)

فایل ZIP را با **Extract All** کامل باز کنید و داخل پوشهٔ `AtlasScout` روی **AtlasScout.exe** دوبار کلیک کنید. این نسخه به نصب Python یا Node.js نیاز ندارد. همهٔ فایل‌های کنار EXE و پوشهٔ `_internal` باید حفظ شوند. اولین استفاده، مدل‌های هوش مصنوعی را دانلود می‌کند؛ نقشه و دریافت تصاویر جدید اینترنت می‌خواهند.

این بسته در [ساخت ویندوز شمارهٔ ۱](https://github.com/davidkordmir-source/S/actions/runs/39730704350) ساخته و آزمایش شد: ۳۰ آزمون، بازشدن رابط در خود EXE، دریافت پنج تصویر واقعی PDOK و استنتاج تصویر و متن فارسی و انگلیسی در همان EXE همگی موفق بودند.

## وضعیت واقعی نسخه

- رابط فارسی راست‌به‌چپ، نقشه، انتخاب شعاع، ورود مجموعه تصاویر، کتابخانهٔ محلی، عملیات پس‌زمینه و خروجی GeoJSON پیاده‌سازی شده‌اند.
- نمایهٔ تصاویر با CLIP و نمایهٔ متن با مدل چندزبانهٔ سازگار با همان فضای برداری ساخته می‌شوند. هیچ پاسخ یا نتیجهٔ نمایشی از پیش‌ساخته در برنامه وجود ندارد.
- دریافت آنلاین برای محدوده‌های کوچک هلند و مرکز پیش‌فرض آمستردام نوشته شده است. تصاویر مناطق دیگر را می‌توان به‌صورت مجموعهٔ دارای مختصات وارد کرد.
- دریافت واقعی **۳۰ تصویر هوایی** از PDOK، نمایه‌سازی با CLIP و جست‌وجوی واقعی تصویر، متن فارسی و متن انگلیسی در محیط توسعه تأیید شدند. عکس مرجع در اولین رتبه با امتیاز شباهت **۰٫۹۹۹۶۹** برگردانده شد. این یک بررسی سلامت بازیابی است، نه اندازه‌گیری دقت روی ساختمان‌های ناشناخته.
- بارگذاری مدل‌ها در یک فرایند تازه با حالت آفلاین نیز موفق بود. سه فایل بزرگ مدل با SHA-256 موجود در کش Hugging Face تطبیق داده شدند. آزمون‌های واحد و آزمون رابط مستقل همچنان از مدل جایگزین مخصوص آزمون استفاده می‌کنند؛ آن‌ها را با بررسی واقعی بالا اشتباه نگیرید.
- هر دو نقشهٔ خیابانی و هوایی در رابط با دادهٔ واقعی بارگذاری شدند. جست‌وجوی واقعی و انتخاب نتیجه روی نقشه بدون خطای جاوااسکریپت اجرا شد. ۳۰ آزمون خودکار، آزمون کامل رابط و ساخت TypeScript نیز موفق بودند.
- فایل EXE نسخهٔ `atlas-v0.1.0-preview.1` روی ویندوز ساخته و در GitHub Releases منتشر شده است. اجرای رابط و هوش مصنوعی در خود بسته روی runner ویندوز تأیید شدند؛ دقت شناسایی ساختمان ناشناخته همچنان نیازمند ارزیابی جداگانه است.

این نسخه یک موتور جست‌وجوی جهانی نیست. جست‌وجو فقط بین تصاویر واردشده و نمایه‌شده انجام می‌شود. تطبیق نمای خیابانی با سقف ساختمان قابل تضمین نیست. امتیاز نمایش‌داده‌شده شباهت کسینوسی است، نه درصد اطمینان یا تأیید هویت ساختمان. دقت روی عکس‌های هوایی واقعی باید جداگانه اندازه‌گیری شود.

## اجرای سورس برای توسعه روی ویندوز

نیازمندی‌ها: Windows 10/11 نسخهٔ ۶۴بیتی، Python **3.12 x64** و Node.js **22.12 یا جدیدتر**. برای دانلود وابستگی‌ها و دو مدل، چند گیگابایت فضای آزاد و اینترنت لازم است. اجرای اولیه روی CPU انجام می‌شود؛ ۸ گیگابایت RAM یا بیشتر توصیه می‌شود.

در PowerShell، داخل پوشهٔ پروژه:

```powershell
.\scripts\setup-windows.ps1
.\.venv\Scripts\python.exe -m atlas
```

اگر سیاست اجرای PowerShell اسکریپت محلی را مسدود کرد، آن را مطابق سیاست سازمان یا تنظیمات حساب خود اجرا کنید. برنامه برای کار عادی به دسترسی Administrator نیاز ندارد.

مسیر پیش‌فرض داده‌ها، تصاویر، مدل‌ها و گزارش خطا:

```text
%LOCALAPPDATA%\AtlasScout
```

می‌توان متغیر `ATLAS_DATA_DIR` را به پوشهٔ قابل‌نوشتن دیگری تنظیم کرد. هیچ کلید API برای پردازش محلی لازم نیست. نام کاربری یا توکن Hugging Face را صرفاً به علت پیام نرخ درخواست عمومی اضافه نکنید؛ این مدل‌ها عمومی‌اند.

### ساخت بستهٔ قابل‌انتقال ویندوز

روی **خود ویندوز**:

```powershell
.\scripts\build-windows.ps1
```

این دستور وابستگی‌ها و رابط را آماده می‌کند، آزمون‌ها را اجرا می‌کند و سپس با PyInstaller بسته می‌سازد:

```text
dist\AtlasScout\AtlasScout.exe
dist\AtlasScout-Windows-x64.zip
```

تمام پوشهٔ `AtlasScout` باید کنار فایل اجرایی باقی بماند. مدل‌ها داخل بسته نیستند و در اولین استفاده دانلود و در مسیر داده‌ها نگهداری می‌شوند. بسته فعلاً نصب‌کننده یا امضای دیجیتال ندارد. workflow به نام **Windows desktop build** در GitHub Actions بسته را می‌سازد و رابط و استنتاج واقعی هوش مصنوعی را در EXE آزمایش می‌کند. انتشار preview تنها پس از موفقیت این بررسی‌ها انجام می‌شود.

## استفاده

۱. از بخش تنظیمات، مدل‌ها را دانلود کنید؛ یا اجازه دهید هنگام اولین نمایه‌سازی بارگذاری شوند.

۲. روی نقشهٔ هلند یک مرکز انتخاب کنید. شعاع بین ۱۰۰ تا ۶۰۰ متر است. «دریافت حداکثر ۳۰ تصویر» نزدیک‌ترین ساختمان‌های قابل‌استفاده را آماده می‌کند. سرویس حداکثر هزار ردپای ساختمان را در محدوده برمی‌گرداند؛ این دریافت بررسی کامل همهٔ ساختمان‌های شهر نیست. تصاویر موجود مجدداً دانلود نمی‌شوند.

۳. «ساخت نمایه» را بزنید. پردازش مرحله‌به‌مرحله در SQLite ذخیره می‌شود و با اجرای دوباره از تصاویر باقی‌مانده ادامه می‌یابد.

۴. عکس از بالا یا توضیح بدهید؛ مثلاً «ساختمان با سقف قرمز و حیاط بزرگ». جست‌وجو به‌صورت پیش‌فرض به دایرهٔ انتخاب‌شده محدود است. برای جست‌وجوی کل کتابخانه، گزینهٔ «جست‌وجو فقط در محدودهٔ انتخابی» را خاموش کنید.

۵. با کلیک روی نتیجه، محل را ببینید یا مختصاتش را کپی کنید. نتایج را می‌توان به GeoJSON صادر کرد. لغو عملیات در مرز مرحله‌ها انجام می‌شود؛ دانلود یا استنتاج جاری ممکن است پیش از توقف کامل شود.

نقشهٔ زمینه و دریافت تصاویر جدید اینترنت می‌خواهند؛ جست‌وجو در کتابخانهٔ آماده با مدل‌های ذخیره‌شده، به سرویس استنتاج ابری وابسته نیست. استفاده از کش آفلاین در فرایند تازهٔ Linux تأیید شده است؛ دستگاه ویندوز مقصد همچنان به بررسی جداگانه نیاز دارد.

## ورود تصاویر یک منطقهٔ دلخواه

یک فایل ZIP شامل `buildings.json` در ریشه و تصاویر بسازید:

```text
collection.zip
  buildings.json
  images/
    roof-01.jpg
    roof-02.png
```

محتوای `buildings.json`:

```json
{
  "buildings": [
    {
      "id": "building-001",
      "title": "نام اختیاری ساختمان",
      "lat": 52.3728,
      "lon": 4.8936,
      "image": "images/roof-01.jpg",
      "source": "نام منبع و اطلاعات مجوز تصویر"
    }
  ]
}
```

مختصات با استاندارد WGS84، عرض و طول جغرافیایی اعشاری هستند. هر تصویر باید متعلق به ساختمان همان مختصات باشد. محدودیت‌ها: ۲۰۰ ساختمان در هر مجموعه، ZIP تا ۸۰ مگابایت، تصویر تا ۱۵ مگابایت و ۲۵ میلیون پیکسل. تصاویر هنگام ورود به JPEG با حداکثر ضلع ۱۰۲۴ پیکسل تبدیل می‌شوند و اصل مجموعه تغییر نمی‌کند. مسیرهای خارج از ZIP، نام‌های تکراری و مختصات نامعتبر پذیرفته نمی‌شوند. تکرار ورود همان شناسه و مختصات، تصویر را به‌روزرسانی و نمایهٔ قبلی آن را باطل می‌کند.

پس از ورود مجموعه، مرکز انتخابی به اولین ساختمان منتقل می‌شود. برای مجموعهٔ پراکنده، فیلتر محدوده را خاموش کنید. کتابخانه فعلاً آخرین ۲۰۰ ساختمان را برای نمایش نقشه و کارت‌ها برمی‌گرداند؛ جست‌وجو روی تمام تصاویر نمایه‌شده انجام می‌شود.

## داده‌ها و مدل‌ها

- ردپای ساختمان: سرویس WFS مربوط به BAG در PDOK، با تبدیل مختصات RD New / EPSG:28992 به WGS84.
- تصویر هوایی: WMS مربوط به PDOK Luchtfoto RGB. لایهٔ تصویر ابتدا از GetCapabilities انتخاب می‌شود. سرویس‌ها و مجوز جاری آن‌ها باید پیش از توزیع محصول نهایی بررسی شوند؛ دسترسی عمومی به‌تنهایی مجوز هر نوع بازتوزیع نیست.
- نقشهٔ زمینه: OpenStreetMap، با انتساب منبع. کاشی‌های نقشه برای نمایش تعاملی استفاده می‌شوند و دانلود انبوه ندارند.
- تصویر: `sentence-transformers/clip-ViT-B-32`.
- متن: `sentence-transformers/clip-ViT-B-32-multilingual-v1`، آموزش‌دیده برای نگاشت متن چندزبانه به همان فضای ۵۱۲بعدی تصویر.

وزن‌ها به این نسخه‌های دقیق متصل‌اند:

```text
image: 327ab6726d33c0e22f920c83f2ff9e4bd38ca37f
text:  58edf8cada9e398793dca955574a48cbb7f18be2
```

نسخهٔ نمایه شامل شناسهٔ این وزن‌هاست. تغییر مدل یا وزن‌ها مستلزم تغییر `INDEX_VERSION` و بازسازی نمایه است. برای تولید نهایی، مجوز مدل‌ها، تاریخ تصاویر و دقت روی مجموعهٔ ارزیابی نیز باید ثبت شوند.

نمایش نقشه از مسیر محلی برنامه استفاده می‌کند تا همان تنظیمات معتبر TLS و پراکسیِ دریافت تصاویر را رعایت کند. مقصدهای دریافت کاشی ثابت‌اند. فقط کاشی‌های درخواست‌شدهٔ نمای فعلی دریافت می‌شوند؛ کش محدود است، زمان اعتبار اعلام‌شدهٔ سرویس رعایت می‌شود و پاسخ‌های `no-store` روی دیسک کش نمی‌شوند.

دامنه‌های موردنیاز: `service.pdok.nl`، `huggingface.co` و میزبان‌های دانلود آن در `*.huggingface.co` و `*.hf.co`؛ `tile.openstreetmap.org` برای نقشهٔ زمینه. نصب از رجیستری‌های استاندارد PyPI، npm و PyTorch CPU انجام می‌شود. بررسی TLS یا امضای بسته‌ها نباید غیرفعال شود. برنامهٔ محلی فقط روی loopback گوش می‌دهد و API آن نشست تصادفی هر اجرا را می‌خواهد.

## توسعه و آزمون

روی Linux برای توسعهٔ منطق و رابط، داخل همین checkout:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python -m pip install --no-deps -e .
cd ui
npm ci
npm run build
cd ..
ATLAS_DATA_DIR="$PWD/.atlas-data" .venv/bin/python -m atlas --serve --port 8765
```

حالت `--serve` فقط برای توسعه و آزمایش داخلی است؛ برنامهٔ ویندوز با `python -m atlas` در پنجرهٔ Qt باز می‌شود. نشانی نشست در خروجی توسعه فقط برای همان ماشین و همان اجراست.

```bash
.venv/bin/pytest -q
.venv/bin/ruff check src tests scripts
cd ui && npm run build
```

آزمون رابط اختیاری به Python دارای Playwright و Chromium نیاز دارد. ابتدا رابط را build کنید، سپس از ریشهٔ پروژه:

```bash
python scripts/smoke-ui.py
```

این آزمون یک سرور موقت مستقل با مدل جایگزین آزمون اجرا می‌کند و ورود مجموعه، نمایه‌سازی، دو روش جست‌وجو، انتخاب نتیجه، خروجی، پنجره‌ها و شکست شبکه را بررسی می‌کند. **آزمون دقت هوش مصنوعی نیست.** مرورگر را می‌توان با `CHROMIUM_EXECUTABLE` مشخص کرد. آزمون‌های دادهٔ مصنوعی هرگز به برنامهٔ اصلی تزریق نمی‌شوند.

پس از آماده‌شدن کتابخانهٔ واقعی، بررسی استنتاج و بازیابی با مدل واقعی و کش آفلاین:

```bash
ATLAS_DATA_DIR="$PWD/.atlas-data" .venv/bin/python scripts/validate-live.py --offline
```

در اجرای تأییدشده، ۳۰ تصویر نمایه‌شده وجود داشت، همان تصویر با امتیاز ۱ در اولین رتبه بازگشت و شباهت برداری دو عبارت هم‌معنای فارسی و انگلیسی ۰٫۹۷۲۷۲ بود. این نتیجه دقت یافتن ساختمان ناشناخته را اندازه‌گیری نمی‌کند. `--offline` بارگذاری را به وزن‌های ذخیره‌شده محدود می‌کند و هیچ تصویر جدیدی دریافت نمی‌کند.

برای آزمون بازشدن پنجرهٔ بومی، `python -m atlas --smoke-test` و برای آزمون مدل‌ها و تصاویر واقعی، `python -m atlas --ai-smoke-test` استفاده می‌شود. در CI همین دو گزینه با **خود فایل AtlasScout.exe** اجرا و تأیید شدند. حالت دوم مدل‌های عمومی را بارگذاری و پنج تصویر واقعی از PDOK دریافت می‌کند؛ اینترنت و فضای کش لازم دارد.

ساختار کد: `src/atlas` منطق، ذخیره‌سازی، دریافت تصاویر و پنجرهٔ دسکتاپ؛ `ui/src` رابط؛ `tests` آزمون‌ها؛ `scripts` ابزارهای نصب و ساخت. هیچ نتیجهٔ دقت، فایل EXE یا دسترسی آنلاینِ تأییدنشده را آماده تلقی نکنید.
