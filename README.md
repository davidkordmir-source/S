# اطلس آفلاین — Atlas Scout Offline

برنامهٔ دسکتاپ **Windows 10/11 x64** برای آموزش با نمونه‌های خودتان و جست‌وجو داخل تصویر ماهواره‌ای که وارد می‌کنید. رابط فارسی داخل پنجرهٔ بومی Qt اجرا می‌شود. تصویر، نمونه‌ها، آموزش، جست‌وجو و خروجی‌ها محلی هستند؛ نسخهٔ آفلاین، هر دو مدل هوش مصنوعی را همراه دارد و حتی در اولین اجرا به اینترنت نیاز ندارد.

## دریافت نسخهٔ ویندوز

[دانلود مستقیم نسخهٔ آفلاین ویندوز — حدود ۱٫۳۷ گیگابایت](https://github.com/davidkordmir-source/S/releases/download/atlas-v0.2.0-offline.2/AtlasScout-Offline-Windows-x64.zip)

[صفحهٔ انتشار و فایل SHA-256](https://github.com/davidkordmir-source/S/releases/tag/atlas-v0.2.0-offline.2)

بستهٔ نسخهٔ **۰.۲ آفلاین** نام `AtlasScout-Offline-Windows-x64.zip` دارد. فایل ZIP را با **Extract All** کامل استخراج کنید، پوشهٔ `AtlasScout` را باز کنید و روی **AtlasScout.exe** دوبار کلیک کنید. نصب Python و Node.js لازم نیست. تمام فایل‌های کنار EXE و پوشهٔ `_internal` باید حفظ شوند؛ مدل‌ها و مبدل ECW داخل همین پوشه هستند. نسخهٔ قدیمی ۰.۱، دریافت آنلاین تصاویر داشت و بستهٔ آفلاین نیست.

ساخت جدید ابتدا در GitHub Actions روی ویندوز آزمایش می‌شود و تنها پس از موفقیت آزمون‌ها در Releases قرار می‌گیرد. بستهٔ قابل‌انتقال فعلاً نصب‌کننده و امضای دیجیتال ندارد. ۸ گیگابایت RAM و چند گیگابایت فضای آزاد توصیه می‌شود؛ کارت گرافیک لازم نیست.

نسخهٔ `atlas-v0.2.0-offline.2` در [اجرای موفق ویندوز شمارهٔ ۲](https://github.com/davidkordmir-source/S/actions/runs/39740452605) ساخته و منتشر شد. بازشدن رابط و آموزش، جست‌وجو، بازآموزی و مدل‌های متن در خود EXE با اتصال‌های بیرونی مسدودشده موفق بودند. آزمون کنترل‌شده سلامت فرایند را بررسی می‌کند؛ دقت روی تصاویر ماهواره‌ای ناشناخته هنوز اندازه‌گیری نشده است. ۳۷ آزمون محلی و آزمون کامل رابط نیز موفق بودند. checksum ثبت‌شدهٔ GitHub با `SHA256SUMS.txt` تطبیق داده شد و درخواست بخشی از لینک، امضای معتبر ZIP را برگرداند.

```text
SHA256: 3a216ea9288b18563acb4a28418cc172fb8435f9f48eba782f897885d9ded259
```

## استفاده، از تصویر تا نتیجه

۱. **انتخاب تصویر:** فایل ماهواره‌ای خودتان را وارد کنید. منطقه محدود نیست؛ برنامه روی همین فایل کار می‌کند. چرخ ماوس برای بزرگ‌نمایی و ابزار جابه‌جایی برای حرکت روی تصویر است.

۲. **ساخت هدف:** نامی مثل «ساختمان با سقف قرمز» بنویسید و + را بزنید. ابزار **نمونه درست** را انتخاب کنید و دور چیزهایی که می‌خواهید پیدا شوند کادر بکشید. با **نمونه غلط** دور موارد مشابه ولی نامطلوب کادر بکشید. همچنین می‌توانید چند فایل عکس نمونه را یک‌جا وارد کنید.

۳. **آموزش:** حداقل **۲ نمونهٔ درست و ۲ نمونهٔ غلط** لازم است. ۵ تا ۲۰ نمونهٔ متنوع از هر نوع برای شروع بهتر است. کادرها را نزدیک هدف، با مقیاس و زاویه‌های متنوع انتخاب کنید؛ نام هدف به‌تنهایی جای نمونه‌ها را نمی‌گیرد. «آموزش با نمونه‌های من» را بزنید.

۴. **جست‌وجو:** اندازهٔ تقریبی هدف به **پیکسل روی تصویر اصلی** را بررسی کنید؛ برنامه آن را از نمونه‌های مثبت پیشنهاد می‌کند. جست‌وجو در سه اندازه انجام می‌شود. برای تصویر بزرگ، ابزار **محدوده جست‌وجو** را بزنید و بخش موردنظر را انتخاب کنید. «جست‌وجو روی تصویر» نتیجه‌ها را روی همان تصویر مشخص می‌کند.

۵. **بهبود:** روی کارت نتیجه کلیک کنید تا کادرش بزرگ شود. دکمه‌های **درست / غلط** نتیجه را به نمونه‌ها اضافه می‌کنند. پس از هر تغییر نمونه، آموزش را دوباره اجرا کنید و جست‌وجو کنید. تغییر نمونه‌ها، آموزش قبلی را تا زمان بازآموزی نامعتبر می‌کند.

۶. **ذخیره:** خروجی **CSV** مختصات پیکسلی و امتیاز مدل، و **PNG نشانه‌گذاری‌شده** موجود است. «ذخیرهٔ آموزش» یک ZIP از نمونه‌ها می‌سازد؛ در دستگاه دیگر با «ورود بستهٔ آموزشی» وارد و یک‌بار آموزش دهید. تمام تصاویر و آموزش‌ها پس از بستن برنامه نیز باقی می‌مانند.

حالت **با توضیح**، متن فارسی یا انگلیسی را به‌صورت آفلاین جست‌وجو می‌کند. برای هدف خاص خودتان از نمونه‌های آموزشی استفاده کنید.

## حدود واقعی قابلیت‌ها

- آموزش یک **دسته‌بند Logistic Regression روی ویژگی‌های ثابت CLIP** است؛ نمونه‌ها با چرخش و قرینه‌سازی گسترش داده می‌شوند. این فرایند، بازآموزی کامل شبکهٔ عصبی یا آموزش یک مدل تشخیص شیء از صفر نیست.
- جست‌وجوی چندمقیاسی با پنجره‌های هم‌پوشان و حذف کادرهای تکراری انجام می‌شود. حداکثر ۲۰۰ نتیجه نمایش داده می‌شود. کادرها ناحیهٔ پیشنهادی‌اند و لزوماً مرز دقیق ساختمان نیستند.
- امتیاز مدل **احتمال کالیبره‌شده یا درصد اطمینان نیست**. کاهش آستانه، نتایج بیشتری همراه با خطای احتمالی بیشتر می‌دهد. دقت ماهواره‌ای روی مجموعهٔ ارزیابی مستقل هنوز اندازه‌گیری نشده است؛ وضوح، مقیاس، نوع هدف و تنوع نمونه‌ها اثر دارند.
- هر جست‌وجو حداکثر ۵۰۰۰ پنجره دارد. اگر کل تصویر از این بودجه بیشتر شود، برنامه درخواست محدودهٔ کوچک‌تر یا اندازهٔ هدف بزرگ‌تر می‌کند؛ هیچ بخش تصویر پنهانی کنار گذاشته نمی‌شود. حالت «بررسی فشرده‌تر» پنجره‌های بیشتری ایجاد می‌کند و کندتر است.
- تصویر اصلی: حداکثر **۱۵۰ MiB، ۶۴ میلیون پیکسل و ضلع ۱۶۰۰۰ پیکسل**. فرمت‌های رایج و رسترهای تخصصی جدول پایین پشتیبانی می‌شوند. فایل‌های چندصفحه‌ای یا متحرک از صفحه یا فریم اول خوانده می‌شوند. PSD از تصویر ادغام‌شده خوانده می‌شود. داده‌های عمق بالا و چندباندی به تصویر RGB هشت‌بیتی مناسب جست‌وجو تبدیل می‌شوند؛ دادهٔ علمی اصلی بازنویسی نمی‌شود.
- هر هدف تا ۵۰۰ نمونه؛ فایل نمونه حداکثر ۱۵ MiB و ۱۶ میلیون پیکسل. نمونه‌های ذخیره‌شده حداکثر ضلع ۱۰۲۴ دارند. بستهٔ آموزشی حداکثر ۱۵۰ MiB فشرده و ۲۰۰ MiB پس از بازکردن و مجموع تصاویر ۶۴ میلیون پیکسل دارد.
- مختصات CSV **پیکسلی** هستند: مبدأ گوشهٔ بالا-چپ، X به راست و Y به پایین. ارجاع جغرافیایی GeoTIFF، طول و عرض جغرافیایی و GeoJSON در این نسخه استخراج نمی‌شوند.

## فرمت‌های ورودی نسخهٔ ۰.۲.۱

همین خواننده برای تصویر اصلی، فایل نمونهٔ آموزشی و تصاویر داخل بستهٔ آموزشی استفاده می‌شود. فهرست کامل پسوندها در پنجرهٔ راهنمای برنامه نیز دیده می‌شود.

| گروه | فرمت‌ها |
|---|---|
| رستر ماهواره‌ای و GIS | **ECW نسخهٔ ۲ و ۳**، TIFF/GeoTIFF، JPEG 2000 (JP2/J2K)، ERDAS Imagine (IMG/HFA)، NITF (NTF/NITF)، PCIDSK (PIX) |
| عکس و وب | PNG/APNG، JPG/JPEG/JFIF، WebP، GIF، BMP/DIB، HEIC/HEIF/HIF، AVIF |
| طراحی و سایر تصاویر | PSD ادغام‌شده، TGA، PCX، PPM/PGM/PBM/PNM، SGI/RGB/RGBA، DDS، ICO/ICNS، QOI، XBM/XPM |

خواندن ECW با **GDAL و کتابخانهٔ ECW Read-Only همراه بسته** انجام می‌شود؛ نصب QGIS، مبدل جداگانه یا اتصال اینترنت در دستگاه مقصد لازم نیست. هر دو نسخهٔ ECW با فایل واقعی روی ویندوز در مرحلهٔ آماده‌سازی مبدل آزمایش شدند؛ آزمون خود EXE نیز پیش از انتشار انجام می‌شود. نوشتن یا فشرده‌سازی خروجی ECW در این برنامه وجود ندارد.

رسترهای چندباندی با باندهای مشخص‌شدهٔ قرمز/سبز/آبی، یا در نبود آن‌ها با سه باند اول، نمایش و جست‌وجو می‌شوند. برای رستر یک یا دوباندی، باند اول استفاده می‌شود. دامنهٔ عمق بالا به ۸ بیت تبدیل می‌شود. فایل‌های خاکستری عمق بالا با کشش روشنایی نمایش داده می‌شوند؛ این تبدیل جای پردازش علمی دادهٔ اصلی را نمی‌گیرد. فرمت‌های وابسته به فایل‌های همراه، رمزگذاری‌شده، RAW دوربین، برداری و همهٔ گونه‌های فشرده‌سازی تضمین نمی‌شوند؛ پشتیبانی مطلق از تمام قالب‌های موجود ممکن نیست.

کتابخانه‌ها و مجوزهای مبدل در `_internal/raster/third-party-licenses` هستند. SDK مربوط به ECW اختصاصی و برای خواندن دسکتاپ است؛ برنامه هیچ سرویس شبکه‌ای ECW راه‌اندازی نمی‌کند. مستندات رسمی: [GDAL ECW driver](https://gdal.org/en/stable/drivers/raster/ecw.html).

## آفلاین و ذخیرهٔ داده

ورود فرمت‌های معمول در Linux قابل توسعه و آزمون است. خوانندهٔ تخصصی GDAL/ECW فعلاً داخل بستهٔ ویندوز ارائه می‌شود؛ آزمون‌های ECW در Linux بدون این خواننده skipped می‌شوند و اجرای موفق آن‌ها در CI ویندوز الزامی است.

مدل‌های تصویر و متن از مسیر محلی و با `local_files_only=True` بارگذاری می‌شوند. `HF_HUB_OFFLINE=1` و `TRANSFORMERS_OFFLINE=1` فعال‌اند. رابط هیچ نقشه یا فونت اینترنتی ندارد؛ Qt درخواست‌های بیرونی را مسدود می‌کند و Content Security Policy ارتباط رابط را به سرویس محلی خودش محدود می‌کند. API فقط روی loopback و با نشست تصادفی هر اجرا در دسترس است. هیچ کلید API یا حساب کاربری برای استفاده لازم نیست.

مسیر پیش‌فرض ذخیره:

```text
%LOCALAPPDATA%\AtlasScout\workshop
```

مسیر در پنجرهٔ تنظیمات دیده می‌شود. تصاویر، نمونه‌ها، آموزش و نتایج در همین کامپیوتر ذخیره می‌شوند. با `ATLAS_DATA_DIR` می‌توان ریشه را عوض کرد. گزارش خطا `atlas.log` و خطای شروع `startup-error.log` در ریشهٔ داده‌ها قرار می‌گیرد. کش ویژگی‌ها برای تکرار جست‌وجو و بازآموزی استفاده می‌شود؛ فقط هشت کش آخر جست‌وجو نگه داشته می‌شوند.

## ساخت و توسعه

توسعه و **ساخت بسته** به اینترنت برای دریافت وابستگی‌ها و مدل‌های عمومی نیاز دارد؛ اجرای بستهٔ آماده به اینترنت نیاز ندارد. Python **3.12 x64** و Node.js **22.12+** لازم‌اند.

روی ویندوز، در PowerShell داخل پروژه:

```powershell
.\scripts\setup-windows.ps1
.\.venv\Scripts\python.exe scripts\bundle-models.py
.\.venv\Scripts\python.exe scripts\bundle-raster.py
.\.venv\Scripts\python.exe -m atlas
```

اسکریپت `bundle-raster.py` در مرحلهٔ ساخت، بسته‌های رسمی OSGeo4W و وابستگی‌هایشان را با checksum اعلام‌شده دریافت می‌کند، مجوزهای اصلی را نگه می‌دارد و وجود و عملکرد واقعی درایور ECW را بررسی می‌کند. هیچ نصب‌کننده یا اسکریپت post-install بسته‌ها اجرا نمی‌شود. این آماده‌سازی به اینترنت نیاز دارد؛ اجرای برنامه به اینترنت نیاز ندارد.

برای ساخت ZIP روی **خود ویندوز**:

```powershell
.\scripts\build-windows.ps1
```

خروجی:

```text
dist\AtlasScout\AtlasScout.exe
dist\AtlasScout-Offline-Windows-x64.zip
```

اسکریپت مدل‌ها را در مرحلهٔ ساخت دریافت می‌کند، اندازه و checksum رسمی هر فایل را با نسخهٔ دقیق مخزن تطبیق می‌دهد و فایل‌های واقعی را همراه manifest به بسته اضافه می‌کند. نام فایل‌های کش Xet جای checksum محتوای فایل استفاده نمی‌شود. بررسی TLS یا checksum نباید غیرفعال شود.

مدل‌ها:

```text
sentence-transformers/clip-ViT-B-32
revision: 327ab6726d33c0e22f920c83f2ff9e4bd38ca37f
sentence-transformers/clip-ViT-B-32-multilingual-v1
revision: 58edf8cada9e398793dca955574a48cbb7f18be2
```

نسخهٔ ویژگی‌ها شامل این شناسه‌هاست. تغییر وزن‌ها مستلزم تغییر نسخه و بازآموزی نمونه‌هاست. اطلاعات مدل و مجوزهای آن را در [مدل تصویر](https://huggingface.co/sentence-transformers/clip-ViT-B-32) و [مدل متن](https://huggingface.co/sentence-transformers/clip-ViT-B-32-multilingual-v1) ببینید.

روی Linux برای توسعهٔ منطق و رابط، از checkout موجود استفاده کنید:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python -m pip install --no-deps -e .
npm ci --prefix ui
npm run build --prefix ui
.venv/bin/python scripts/bundle-models.py
ATLAS_DATA_DIR="$PWD/.atlas-data" .venv/bin/python -m atlas --serve --port 8765
```

`--serve` فقط برای توسعه و بررسی داخلی رابط است. برای استفادهٔ عادی ویندوز، EXE پنجرهٔ برنامه را باز می‌کند.

## بررسی کیفیت و اجرای آزمون‌ها

```bash
.venv/bin/python -m pytest -q
.venv/bin/ruff check src tests scripts
npm run build --prefix ui
python scripts/smoke-ui.py
ATLAS_DATA_DIR=/tmp/atlas-offline-check .venv/bin/python -m atlas --ai-smoke-test
```

- آزمون‌های API و رابط از بردارهای قطعی مخصوص آزمون استفاده می‌کنند؛ هیچ‌کدام به برنامهٔ اصلی تزریق نمی‌شود. مسیر ورود تصویر، کادرکشیدن، آموزش، جست‌وجو، بازخورد، بازآموزی، CSV/PNG، بستهٔ آموزشی، محدوده و دو اندازهٔ پنجره بررسی می‌شود. آزمون رابط به Playwright و Chromium نیاز دارد؛ `CHROMIUM_EXECUTABLE` اختیاری است.
- `--ai-smoke-test` **مدل واقعی همراه بسته** را با پوشهٔ دادهٔ جدید و اتصال‌های بیرونی مسدودشده بارگذاری می‌کند؛ آموزش، جست‌وجو روی تصویر دوم، تفکیک نمونهٔ هدف از غیرهدف، بازخورد و بازآموزی، انتقال نمونه‌ها و متن فارسی/انگلیسی را بررسی می‌کند. دادهٔ کنترل‌شده برای سلامت فرایند است، نه اندازه‌گیری دقت شناسایی ساختمان واقعی. نتیجه در `ai-smoke.json` ثبت می‌شود.
- CI ویندوز هر دو گزینهٔ `--smoke-test` و `--ai-smoke-test` را با **خود EXE** اجرا می‌کند. انتشار فقط پس از موفقیت آن‌ها و تولید SHA-256 انجام می‌شود.

نقطهٔ ورود برنامه `atlas.__main__` از `offline_server.py` و `workshop.py` استفاده می‌کند. ماژول‌های قدیمی `server.py`، `imagery.py`، `store.py` و آزمون‌هایشان برای سازگاری توسعه در مخزن باقی مانده‌اند؛ سرویس‌های آنلاین قدیمی در برنامهٔ آفلاین راه‌اندازی نمی‌شوند.
